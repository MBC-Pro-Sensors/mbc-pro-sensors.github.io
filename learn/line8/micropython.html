MBC 循行者 8 路 × Pybricks

三個步驟用 MicroPython 讀循行者

寫 Pybricks 程式一定照這個順序：先匯入函式庫，再建立物件、幫感應器取名字，最後才用這個名字去呼叫功能。左邊一步一步做，右邊的程式會跟著長出來；拖動模擬感應器下面的黑線，就能看到程式會印出什麼。

你的主機：
1

匯入函式庫

程式的第一件事是告訴 Pybricks「我要用循行者的函式庫」。沒有這行，後面寫的 MBC_LINE8 主機看不懂，會出現 NameError。

選一種函式庫（兩種寫法完全一樣，只差 import 那一行）：

  1. 下載函式庫（存成檔案，檔名不要改）：MBC_line8.py（只接循行者 8 路）或 MBC_sensors.py（統一函式庫）；你選的是 MBC_line8.py。
  2. 在 Pybricks Code 左邊檔案區按「Import a file」，把它匯入同一個專案。
  3. 檔名不要改，也不要放進子資料夾。
  4. 回到主程式，在最上面寫下面這幾行（右邊程式標 ① 的地方）。
2

建立物件：幫感應器取名字

一台車可能接好幾個感應器，所以要「建立一個物件」：告訴程式感應器接在哪個孔，並幫它取個名字。之後每次要讀值，都是叫這個名字。

使用功能

寫法都是「line8.功能名稱()」：名字＋小數點＋功能。點一個功能，程式和輸出會換成它的範例。

使用注意

    
    
      
  1. 拔線不會讓程式停。讀不到時回傳上一次讀到的值，從來沒讀到過就回傳 None，電腦畫面印一行提醒；插回去自動恢復。要知道有沒有接好就用 sensor_ok()。在右邊勾「拔掉感應器」可以看到這個情形。循線時拔線，車子會照最後的位置繼續開。
    2. 
      
  2. 10 ms 內重複讀不會變慢。同一組資料 10 ms 內只向感應器讀一次（感應器本來就每 10 ms 更新），一次呼叫好幾個功能沒關係。
    3. 
      
  3. EV3 換一組資料要約 0.5 秒。同一個迴圈裡盡量用同一組：pos100()、width()、edge_l()、edge_r() 一組（循線最常用）；bin_raw()、bitmap()、on_sensors()、junction()、junction_name() 一組；pos8() 單獨一組；ir_ch()、ir_calibration() 一組；device_id()、firmware_version() 放在迴圈外面。SPIKE 沒有這個問題。
    4. 
      
  4. 方向：站在車後面往前看，線在左邊是負數、右邊是正數；第 1 路在最左邊。
    5. 
      
  5. 丟線時會記住最後一側：線完全離開感應器時，pos8() 回傳 −8 或 +8、pos100() 回傳 −100 或 +100（看線最後從左邊還是右邊離開）。循線程式不用另外寫找線的程式，車子會自己往那一側轉回去。要判斷「真的看不到線」就用 width() == 0。
