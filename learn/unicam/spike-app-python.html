MBC 神攝手 × 樂高官方 SPIKE App（Python）

三個步驟用官方 SPIKE App 的 Python 讀神攝手

樂高官方 SPIKE App（教育版）也能寫 Python，不用換韌體。神攝手在 App 裡是一顆顏色感應器，App 不能匯入自己的檔案，所以照這個順序寫：先把讀值小幫手貼在最上面、選好相機模式，再建立物件、幫相機取名字，最後每圈 update() 一次、用名字呼叫功能。左邊一步一步做，右邊的程式會跟著長出來；在模擬的相機畫面裡拖色塊、色紙、積木或線，就能看到程式會印出什麼。

v1 尚未上機驗證數值排法已定案並通過電腦端測試，實機數值（fps、循線門檻、I2C 腳位）上機後可能調整。

1

貼上小幫手、選相機模式

官方 App 的 Python 專案只有一個檔案，不能匯入自己的 .py，所以把「讀值小幫手」整段貼在程式最上面（小幫手開頭也寫了：照抄就好、不用改）。沒有它，後面寫的 UniCamApp 主機看不懂，會出現 NameError。

  1. 打開樂高官方 SPIKE App（教育版，SPIKE Prime 黃色主機），新增專案，選「Python」。
  2. 把右邊標 ① 的程式貼到最上面（小幫手只露第一行，按「顯示小幫手」看全部；「複製程式」一定是完整的）。小幫手也可以單獨下載：MBC_UniCam_App_helper.py（用記事本打開、全選複製）。
  3. 相機插主機 A～F 任一孔，由主機供電；相機要用 SPIKE 版韌體（同一個韌體會自己認出是官方 App 還是 Pybricks）。
  4. 選相機模式：在相機的 MODE 選單選相機模式和子選項，下面點同一個模式編號（模式編號＝相機模式 ×10＋子選項）。
2

建立物件：幫相機取名字

一台車可能接好幾個感應器，所以要「建立一個物件」：告訴小幫手相機接在哪個孔（port.C 來自 from hub import port）、是哪個模式，並幫它取個名字。之後每次讀值都叫這個名字。

相機接在哪個孔？

第二個數字是第 1 步選的模式編號；相機選單也要切到同一個模式（官方 App 讀不到相機現在是哪個模式，小幫手照你寫的拆，不一樣時數字會亂掉）。

3

每圈 update()，再使用功能

官方 App 的程式放在 async def main(): 裡，最後 runloop.run(main()) 讓它開始跑；等待用 await runloop.sleep_ms(100)（不是 Pybricks 的 wait()）。每圈先 cam.update() 讀一次，再用「名字＋小數點＋功能」。功能依相機模式分組，虛線框的功能是別的模式用的，要換模式才能用（點下去會幫你換）。

模擬相機畫面：拖動畫面裡的東西，看右邊的輸出怎麼變

模擬畫面是示意：數值直接用畫面上的位置換算（X 0～159 左→右、Y 0～119 上→下、面積 %＝寬×高÷整個畫面），色相碼是那張色紙／積木本來的顏色（紅 0、黃 40、綠 80、藍 160、紫 200、白桌面 244、黑膠帶 252），不是相機裡面的算法；實際數值會因光線差一些。顏色追蹤假設相機上已經教了 4 色：色 1 紅、色 2 綠、色 3 藍、色 4 黃。物體偵測的形狀是你直接選的（不是相機判斷的），物體 1、2…照面積由大到小排，X、Y 是形狀的質心（白點）、虛線框是外框，角度就是你轉的角度。

from hub import port
import runloop


async def main():

runloop.run(main())

  

  

    
使用注意

    
    
      
  1. 每圈先 update()。小幫手的功能都是拆「最近一次 update() 讀到的 8 byte」；沒 update() 就一直是舊的（一開始全是 0）。
    2. 
      
  2. 模式編號一定要跟相機選單一樣。官方 App 讀不到相機現在的模式，小幫手照 UniCamApp(port.C, 模式) 拆；物體功能用錯模式會出現 ValueError，其他功能不會報錯、只是數字沒有意義。
    3. 
      
  3. 這是官方 App 3 的寫法，跟 Pybricks 不一樣。孔位是 from hub import port 的 port.C（不是 Port.C）、等待是 await runloop.sleep_ms()（不是 wait()），Pybricks 的程式不能直接貼過來。家用版（Robot Inventor）App 的 Python 讀法還沒驗證，這頁是教育版的。
    4. 
      
  4. 位置是格子，不是像素。模式 13、14 是 16×12 格（像素 ≈ 格×10−5），模式 11、12 和物體清單 51 是 8×6 格（像素 ≈ 格×20−10）；(0, 0)＝沒看到。只有模式 52 的物體 1 位置是像素。Y 上＝小；循線偏移線在左＝負、在右＝正（站在車後面往前看）。
    5. 
      
  5. 小幫手只讀 byte 0～7。每個模式讀得到哪些，第 1 步選模式時會寫；讀不到的（數量、面積、循線中段偏移、旗標…）見上面「byte 8～15」或改用 Pybricks MicroPython。顏色要在相機上教，程式改不了目標色。
