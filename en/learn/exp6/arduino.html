MBC SPIKE 6-Way Expander (EXP6) × Arduino

Control EXP6 with Arduino in three steps

An Arduino program goes in this order. First pick your board, wire it up and paste the Communication helpers. Then, in setup(), wake EXP6 up with exp6Begin(). Last, in loop(), send commands and read values (run motors, read angles, read sensors). EXP6 uses a UART serial port, not I2C. Follow the steps on the left, and the program on the right grows with you. Choose what is plugged into each port of the simulated EXP6 to see how the motors turn and what the Serial Monitor shows.

1

Pick a board, wire it up, paste the helpers

Arduino talks to EXP6 over a UART serial port (two wires, TX / RX). It cannot use I2C, and you do not need to install a library. Paste the "Communication helpers" at the very bottom of your program. Then you can send commands with exp6Send() and get data with exp6Receive(). A new EXP6 needs no new firmware: after the first command from Arduino, it switches from "LEGO mode" to "UART mode" by itself.

Which board do you use? (Only the pins change. The program is the same: the helpers pick the serial port for you.)

UNO R3 and Nano have only one hardware serial port (D0 / D1), and USB already uses it. EXP6 sends back a data pack every 0.01 s at a fixed 115200 baud. A software serial port (SoftwareSerial) is not reliable at 115200, and it cannot send commands while it is receiving. So on these boards the program prints "This board ... cannot connect to EXP6" and stops. Please use UNO R4, Mega 2560 or ESP32.

  1. Unplug the USB cable and the battery before wiring. Use a "LEGO 6-pin to Dupont cable" (or a LEGO connector breakout board) on the EXP6 Host port (the port that goes to the controller).
  2. Host pin 3 GND → GND, pin 4 VCC → 5V (pin 4 is also EXP6's "power-on key": without it, EXP6 does not turn on)
  3. Pin 5 (EXP6 receives) → D1 (TX), pin 6 (EXP6 sends) → D0 (RX). The two wires cross over. Pins 1 and 2 are not connected.
  4. The EXP6 XT30 power socket must be connected to a 2~3S lithium battery. The motors and sensors get their power from it. EXP6 does not power the Arduino: power the Arduino with USB or a power bank.
  5. Open the Arduino IDE: File → New, and delete what is already there. Pick your board (for example Arduino UNO R4 Minima).
  6. Paste the "Communication helpers" at the very bottom (marked ① in the program on the right; "Copy program" copies it too). The first two lines are wiring notes, to remind you which wire goes where.
2

Wake EXP6 up and wait until it is ready

setup() runs only once, when the board starts. It opens the serial port, wakes EXP6 up with exp6Begin() (it waits up to 3 s, and also stops the motors and sets the angles to 0), then waits 1.5 s so the motors and sensors can be found. Always wait with exp6Wait(), not delay(): if EXP6 gets no command for more than 0.5 s, it stops the motors by itself (the watchdog).

Use a function

To send a command, write "exp6Send(L1, L2, L3, L4)", or use a "cheat sheet" function from the examples such as motorRun(). To read, first get the newest data pack with exp6Receive(), then read it with exp6Port(port) and exp6Device(port). Click a function, and the program and the Serial Monitor change to its example. The motors on the simulated EXP6 move too.

Simulated EXP6 (seen from above): choose what is plugged into each port, then watch the motors turn and the Serial Monitor on the right

At the start, ports 1 and 2 have motors, port 4 a color sensor, port 5 an ultrasonic sensor and port 6 a force sensor, the same ports the examples use. The simulation is only an illustration: speed 1 counts as 10 degrees per second (a real motor depends on its model), and the sensor values are simplified. The red pointer shows which way the motor shaft points; ↻ = clockwise. When you unplug the Host cable, EXP6 turns off (pin 4 is its power-on key) and the motors stop. exp6Receive() gets no data and gives false. exp6Port() keeps the numbers from the last pack, so every example checks exp6Receive() first. Plug it back in and EXP6 restarts; after the next command from Arduino it switches back to UART mode by itself. For a function that runs once in setup(), loop() is empty, so about 0.5 s later the watchdog stops the motors (a turn that has not finished yet finishes first).

Good to know

    
    
      
  1. Always connect the EXP6 battery and pin 4. The motors and sensors all run on EXP6's own battery (2~3S lithium). Pin 4 is EXP6's "power-on key", and its voltage must match the board's signals (5V for UNO R4 and Mega, 3V3 for ESP32). The EXP6 ports only know LEGO motors and the LEGO SPIKE color, ultrasonic and force sensors.
    2. 
      
  2. Wait with exp6Wait(), not delay(). If EXP6 gets no command from Arduino for more than 0.5 s, it stops the motors by itself (the watchdog). motorRun(1, 50); delay(3000); runs for only 0.5 s; motorRun(1, 50); exp6Wait(3000); runs for 3 s. In code that takes a long time, send exp6Send(1, 0, 0, 0) now and then.
    3. 
      
  3. Unplugging does not stop the program. When there is no data, exp6Receive() gives false (the examples print "No data. Check if a wire is loose."), and exp6Port(), exp6Device() still hold the numbers from the last pack. So check exp6Receive() before every read. Tick "Unplug the EXP6 Host cable" on the right to see this. If EXP6 is not found at power-on, exp6Begin() gives false.
    4. 
      
  4. L1~L4 of every command must be 0~100. If you send the exact same command twice in a row, the second one is skipped (turn-to-angle and reset-angle are not affected). Send a turn-to-angle command only once: EXP6 turns to the angle by itself. If it gets the same command again after it gets there, it turns again.
    5. 
      
  5. A device you just plugged in takes 1~2 seconds to be found (exp6Device() is 0 at first). UNO R3 and Nano cannot be used: USB uses their only hardware serial port. On UNO R4 you do not need to unplug the D0, D1 wires to upload. Set the Serial Monitor to 115200 baud.
