MBC SPIKE 6-Way Expander (EXP6) × Pybricks

Control EXP6 with MicroPython in three steps

A Pybricks program always goes in this order: first import the library, then create an object and give EXP6 a name, and only then use that name to call functions (turn motors, read sensors). Work through the steps on the left and the program on the right grows with you. On the simulated EXP6, choose what is plugged into each expansion port to see how the motors turn and what the program prints.

Your hub: SPIKE Prime (EXP6 only works with SPIKE Prime, not EV3). EXP6 needs its own battery, or the motors will not move.
1

Import the library

The first thing your program does is tell Pybricks "I want to use the EXP6 library". Without this line, the hub does not know what MBC_EXP6 means and you get a NameError. EXP6 has only this one library, so there is nothing to choose.

  1. Download the library (save the file and keep its name): MBC_exp6_obj_Lib.py. The file name is MBC_exp6_obj_Lib.py.
  2. In Pybricks Code, click "Import a file" in the file panel on the left and import it into the same project.
  3. Do not rename the file (the program uses the name MBC_exp6_obj_Lib), and do not put it in a subfolder.
  4. Go back to your main program and type the lines below at the very top (marked ① in the program on the right).
2

Create an object: give EXP6 a name

Now you "create an object": you tell the program which hub port the EXP6 Host cable is plugged into, and you give it a name. From then on, you use this name every time you turn a motor or read a sensor.

Which hub port is the EXP6 Host cable plugged into?

Do you want multitasking?

The 3 in the program is the hub port: 1 to 6 = A to F (write a number only, not Port.C). The first number inside the brackets of the functions later is the expansion port on EXP6, 1 to 6. Do not mix them up.

3

Use the functions

You always write "exp6.function_name(expansion port, …)": the name, a dot, then the function. The first number in the brackets is usually the expansion port on EXP6, 1 to 6. Click a function and the program and output switch to its example. The motors on the simulated EXP6 move to match.

Simulated EXP6 (seen from above): choose what is plugged into each expansion port, then watch the motors turn and see what is printed on the right

At the start, expansion ports 1 and 2 have motors, port 4 a colour sensor, port 5 an ultrasonic sensor and port 6 a force sensor, the same ports the examples use. The simulation is only an illustration: 1% motor speed counts as 10 degrees per second (a real motor depends on its model), and the sensor values are simplified. The red pointer shows which way the motor shaft points; ↻ = clockwise. When you unplug the expander, the motors stop and every reading becomes 0 (not the last value). The library prints its connection warnings in both Chinese and English, so you see them here exactly as on the hub. About 0.5 seconds after the program ends, the EXP6 watchdog stops the motors (a turn that has not finished yet finishes first). With multitasking and the library's run_task, the motors stop the moment the program ends.

35 functions (everything in the library), each with a short example. Actions such as turning or stopping a motor usually go outside the loop and run once. Things to know

    
    
      
  1. Always connect the EXP6 battery. Every motor on the expansion ports runs on EXP6's own battery (a 2S LiPo is recommended). With only the Host cable and no battery, nothing moves. EXP6 only accepts LEGO motors and the LEGO SPIKE colour, ultrasonic and force sensors. Plug MBC sensors straight into the hub.
    2. 
      
  2. Do not mix up the two kinds of port number. The 3 in MBC_EXP6(3) is the hub port (1 to 6 = A to F). The 1 in exp6.motor_run(1, 50) is the expansion port on EXP6 (the 1 to 6 printed on the board).
    3. 
      
  3. Wait with keep_alive_wait(), not wait(). If EXP6 hears nothing from the hub for more than 0.5 seconds, it stops the motors by itself (a watchdog for safety; you cannot turn it off). In the normal style, always write waits as exp6.keep_alive_wait(milliseconds). If a calculation takes a long time, call exp6.keep_alive() once in the middle. With multitasking, use the library's run_task(): it sends the heartbeat in the background, so plain await wait() is fine.
    4. 
      
  4. Unplugging the expander does not stop the program. Readings become 0 (not the last value), actions cannot be sent, and the computer prints a warning at most once a second. Plug it back in and it reconnects by itself. To check whether it is connected, read exp6.connected. Tick "Unplug the expander" on the simulated EXP6 to see this.
    5. 
      
  5. A turn command moves on right away and does not wait for the turn to finish. After motor_run_degrees() or motor_track_target(), wait a little, or keep reading the angle until it gets there. If you send a new turn before the last one is done, the new one is dropped. Right after power-on, the motors need about 1 second to get ready, so start your program by waiting until get_device_id(port) == 5. End your program with stop_all(1) so every motor stops.
