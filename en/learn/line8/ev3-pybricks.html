MBC Pathfinder 8-Way (Line8) × EV3 Pybricks

Read the Pathfinder on the EV3 with MicroPython in three steps

MicroPython on the EV3 always goes in this order. First import. Then create an object and give the sensor a name. Last, use that name to read values. First pick Pybricks v4 or EV3 MicroPython v2 above. Then follow the steps on the left, and the program on the right grows with you. Drag the black line under the sensor simulator to see what the program prints.

Your software:
1

Import the libraryImport the modules

The first thing your program does is tell Pybricks: "I want to use the Pathfinder library". Without this line, the hub does not know what MBC_LINE8 means, and you get a NameError.

Pick one library. Both work the same way. Only the import line is different.

  1. Download the library (save the file and keep its name): MBC_line8.py (only this sensor) or MBC_sensors.py (the all-in-one library). You picked MBC_line8.py.
  2. Open code.pybricks.com in Chrome. Follow the steps on the site to put the Pybricks firmware on the EV3 (the release version already includes the EV3 firmware).
  3. Press "Import a file" in the file list on the left. Import the library into the same project.
  4. Do not rename the file, and do not put it in a sub-folder.
  5. Go back to your main program. Write the lines below at the very top (marked ① in the program on the right).

EV3 MicroPython v2 cannot use the MBC library (it does not have the PUPDevice the library needs). Use the built-in Ev3devSensor instead, and read the sensor "modes" directly. You do not need to download any file.

  1. Start the EV3 from the official LEGO EV3 MicroPython microSD card.
  2. In VS Code, install the "LEGO MINDSTORMS EV3 MicroPython" extension and create a new project.
  3. Open main.py. Write the lines below at the very top (keep line 1, the one that starts with #!).
  4. Press F5 to download it to the EV3 and run it.

Which port is the sensor on?

Turn on multitasking?

The 1 in the program is the port number: EV3 1~4 = S1~S4. You can also write Port.S1, but then you also need from pybricks.parameters import Port.

Ev3devSensor needs the form Port.S1 (a plain number does not work), so step 1 also imports Port.

3

Use a functionRead a value

You always write "line8.function_name()": the name, a dot, then the function. Click a function, and the program and output change to its example.

You write "line8.read('mode name')[which one]". Each mode sends back several numbers at once. Use [0], [1]… to take one of them (counting starts at 0). Use only one mode in the same loop: the EV3 needs about 0.5 s every time it changes mode. Click a reading, and the program and output change to its example.

Sensor simulator (looking from behind the robot): drag the black line and watch the output on the right

The simulator is only a picture. The maths is simpler than the real thing, so a real sensor may be off by a channel or two. Light value 0 = black, 100 = white. A red ring = that channel sees the line (light value below 50).

Good to know

    
    
      
  1. Unplugging works differently in the two programs. Pybricks v4 with the MBC library: when the sensor cannot be read, you get the last value it read (or None if it has never been read). The computer prints one warning line, and the program keeps running. Plug it back in and it works again by itself. To check the cable, use sensor_ok(). EV3 MicroPython v2 with Ev3devSensor: you get an OSError and the program stops. Plug the sensor back in and run the program again. Tick "Unplug the sensor" on the right to see both.
    2. 
      
  2. On the EV3, changing mode takes about 0.5 s. Try to use one mode in the same loop (the "Mode N" on each card). pos100(), width(), edge_l(), edge_r() are mode 2 (the most used for line following). bin_raw(), bitmap(), on_sensors(), junction(), junction_name() are mode 3. pos8() is mode 0. ir_ch(), ir_calibration() are mode 1. Put device_id() and firmware_version() (mode 5) outside the loop.
    3. 
      
  3. Direction: stand behind the robot and look forward. Line on the left = negative, line on the right = positive. Channel 1 is on the far left.
    4. 
      
  4. It remembers the last side when the line is lost. When the line leaves the sensor completely, line position gives −8 or +8 and fine position gives −100 or +100, depending on the side where the line left. So the robot turns back towards that side by itself. To check "I really cannot see a line", use line width = 0.
    5. 
      
  5. What the EV3 cannot read: read_all() is SPIKE only. The EV3 does not get "line segments", so the library works out junction() from the bitmap. With EV3 MicroPython v2, work it out yourself or use Pybricks v4. The bitmap, ID and firmware version (modes 3 and 5) need sensor firmware v4.0 or later.
