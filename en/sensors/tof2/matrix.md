# Laser Ranger 2-ch × MATRIX Mini R4

[🔙 Back to Laser Ranger 2-ch](/en/sensors/tof2/index.md)

The MATRIX edition of the Laser Ranger 2-ch plugs into a Mini R4 I2C port at address `0x22` and can be read two ways: **A. stock colour-sensor blocks** (no library change, R~K = seven 0~255 numbers) or **B. the LauMo big channel** (swap in the big-channel library, one 30-byte packet with everything). They need different library files and cannot be mixed.

## Wiring

<figure class="ref-fig"><img src="/images/figures/tof2/wiring-matrix.svg" alt="Laser Ranger 2-ch × MATRIX Mini R4" loading="lazy"></figure>

Use the stock MATRIX 4-pin sensor cable on I2C1 or I2C2 and pick that port in the block.

## A. Stock blocks (0x22)

The "colour sensor → R / G / B / C / M / Y / K" blocks each return one 0~255 number. ⚠️ Do not use the stock H / S / V or colour-ID blocks (the host computes them from R, G, B; meaningless here); the grayscale and colour-number blocks were removed by MATRIX.

| Block | Content | Decode |
| :--- | :--- | :--- |
| R | [left distance (cm)](/en/sensors/tof2/reference.md#v01) |  |
| G | [right distance (cm)](/en/sensors/tof2/reference.md#v02) |  |
| B | [nearer distance (cm)](/en/sensors/tof2/reference.md#v03) | B（命令 12 也回較近，schema 不收 12） |

```cpp
// MATRIXblock → Arduino：stock library
int r = MiniR4.I2C1.MXColor.getColor(R);   // left distance (cm)
```

## B. Big channel (LauMo library)

After swapping in the `MiniR4ColorSensorExt` big-channel library ([download](/en/downloads.md)) the same blocks become pointer reads: ColorID resets the pointer and returns the status byte, Blue reads 1 byte, Green 1 signed byte, Saturation 2 bytes, Hue 2 signed bytes, Value a 4-byte float, Red advances the pointer by the size of the last read.

<figure class="ref-fig"><img src="/images/figures/common/packet-big30.svg" alt="LauMo 30-byte packet" loading="lazy"></figure>

| byte | Block | Content | Note |
| :--- | :--- | :--- | :--- |
| 0 | Blue | [left distance (cm)](/en/sensors/tof2/reference.md#v01) |  |
| 1 | Blue | [right distance (cm)](/en/sensors/tof2/reference.md#v02) |  |
| 2 | Blue | [nearer distance (cm)](/en/sensors/tof2/reference.md#v03) |  |
| 5~6 | Saturation | [left distance (mm)](/en/sensors/tof2/reference.md#v04) | #67 追加（MATRIX 定案 §4：[5..6] 小端） |
| 7~8 | Saturation | [right distance (mm)](/en/sensors/tof2/reference.md#v05) | #67 追加（[7..8] 小端） |
| 3 | Blue | [init bitmap](/en/sensors/tof2/reference.md#v06) |  |
| 4 | Blue | [fault bitmap](/en/sensors/tof2/reference.md#v07) |  |
| 24 | ColorID | [F3 status flags](/en/sensors/tof2/reference.md#flags) |  |
| 25 | Cyan | F1 completion count | 0 |
| 26 | Magenta | F2 completion count | 0 |
| 27 | Yellow | device ID | 0x29 |
| 28 | Key | hw[0] | 2 |
| 29 | — | CRC-8 | poly 0x07 over bytes 0~28; checked by the library |

**Actions**：none (Cyan / Magenta / Yellow / Key only return bytes 25~28)

### Arduino code (MATRIXblock Arduino mode)

```cpp
// big channel: read byte n (uint8) / 2 bytes from n (uint16 little-endian)
uint8_t bigU8(uint8_t n) {
  MiniR4.I2C1.MXColor.getColorID();                 // pointer back to byte 0
  uint8_t v = MiniR4.I2C1.MXColor.getColor(B);      // read byte 0
  for (uint8_t i = 0; i < n; i++) { MiniR4.I2C1.MXColor.getColor(R); v = MiniR4.I2C1.MXColor.getColor(B); }   // Red = advance 1
  return v;
}
uint16_t bigU16(uint8_t n) {
  MiniR4.I2C1.MXColor.getColorID();
  MiniR4.I2C1.MXColor.getColor(B);
  for (uint8_t i = 0; i < n; i++) MiniR4.I2C1.MXColor.getColor(R);
  return (uint16_t)MiniR4.I2C1.MXColor.getS();      // Saturation = read 2 bytes
}
int16_t bigI16(uint8_t n) {
  MiniR4.I2C1.MXColor.getColorID();
  MiniR4.I2C1.MXColor.getColor(B);
  for (uint8_t i = 0; i < n; i++) MiniR4.I2C1.MXColor.getColor(R);
  return (int16_t)MiniR4.I2C1.MXColor.getH();       // Hue = read signed 2 bytes
}
```

```cpp
int leftCm = bigU8(0);   // left distance (cm)
```

## Sources and assumptions

Generated by `_build/gen-reference.mjs` from `_build/protocol/tof2.json` (single source of truth, transcribed from the 2026-10-21 protocol decisions).

- 共識 #8：08 左右平均 mm 補進 I2C／mBlock 值表（定案 §5 已列）。
- B-7：大通道 [24] 由 sensorInitOk 改成 F3 狀態旗標（統一格式），[25..26] = 0（沒有動作）、[27] = 0x29、[28] = 2；[0..4] 不動、追加 [5..6] 左 mm、[7..8] 右 mm（u16 小端）。
- 0x22 命令 4~12 不動（4 左、5 右、6 最近、7~11 = 0、12 = 最近）；schema 不收 11/12，所以 12 只寫在 03 的 note。
- EV3：模式 0、2、4 鎖住（照盤點）；模式 1 改 [左,右]×4（index 0/1 各代表左右）、模式 3 改平均 mm、模式 5 改 [左 mm, 右 mm]；模式 1 描述表宣告 int8 −100~100，cm×100/120 在範圍內。
- SPIKE：0/5/7/9 鎖住，另加模式 3 鎖住（網站 sensors/tof2/index.md read(3) = 左／右 cm，共識 #11）；模式 6 改 [左 mm, 右 mm, 平均 mm]；模式 1、2、4、8 維持不動；模式 8 v[0] 改 ID|hw[0]<<8（統一後共用函式）。
- 「左」= 站在車後往前看的左（第 0 顆，XSHUT PA6）；韌體只有 L/R 巨集名，盤點檔標為推測。
- 沒有寫入命令；F8 換位址／EF 重開機用共用的。
- Library rules (command 1 returns 0x43, CRC-8, 5 ms minimum interval) follow the LauMo big-channel library source.
